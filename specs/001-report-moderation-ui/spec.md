**Источник контракта**: `practices/practice_05/contract.md`. Все маршруты, поля, коды ошибок, коды статусов,

## Общие ограничения UI

- Серверный рендеринг (Flask + Jinja), без JavaScript. Все состояния передаются через перерисовку страницы
  (HTTP-код как в контракте) или редирект.
- Весь видимый текст на русском языке.
- Все значения, полученные из запроса или из логики, выводятся экранированными, включая значения полей
  формы при перерисовке.
- Статус выводится текстом (бейдж содержит подпись), цвет не является единственным признаком.
- Клиентские ограничения (`maxlength`) только подсказка; окончательная проверка на сервере.
- Каждая форма действия над доносом содержит скрытое поле `return_query` с текущей query-строкой списка
  (контракт, маршрут смены статуса).

## Соответствие контракту и текущим шаблонам

- Поля формы `name`, `group`, `details`, `vibe_level` и фильтры `vibe_level`, `group`, `q` уже есть в
  текущих шаблонах `index.html` и `reports.html`. Они сохраняются без изменения имён и расположения.
- Добавляется только фильтр `status`, так как он есть в контракте и отсутствует в текущем шаблоне.
- Тексты, которых нет ни в контракте, ни в текущих шаблонах, отмечены в разделе «Тексты вне контракта».

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Отправка доноса с ошибками и повтором (Priority: P1)

Пользователь заполняет форму. При ошибке валидации текст выводится под полем, при дубликате или внутренней
ошибке — блоком над формой. Введённые значения сохраняются.

**Acceptance Scenarios**:

1. **Given** пустое «Имя студента», **When** отправка, **Then** HTTP 422, под полем текст «Укажите имя студента.»,
   значения остальных полей сохранены.
2. **Given** «Имя студента» из одного символа, **When** отправка, **Then** HTTP 422, под полем «Имя студента:
   от 2 до 60 символов.».
3. **Given** «Группа» длиннее 20 символов (обход `maxlength`), **When** отправка, **Then** HTTP 422, под полем
   «Группа: не больше 20 символов.».
4. **Given** «Описание» короче 10 или длиннее 1000 символов, **When** отправка, **Then** HTTP 422, под полем
   «Описание: от 10 до 1000 символов.» или, при пустом значении, «Опишите ситуацию.».
5. **Given** несколько неверных полей, **When** отправка, **Then** HTTP 422, под каждым неверным полем свой текст.
6. **Given** `vibe_level` вне списка, **When** отправка, **Then** HTTP 422, под полем «Уровень вайба» текст
   «Выберите уровень из списка.».
7. **Given** донос-дубликат, **When** отправка, **Then** HTTP 409, над формой блок «Такой донос уже отправлен.
   Измените данные и отправьте снова.», значения сохранены.
8. **Given** внутренняя ошибка, **When** отправка, **Then** HTTP 500, над формой блок «Не удалось отправить
   донос. Попробуйте ещё раз.», значения сохранены.
9. **Given** введены `<b>текст</b>`, **When** страница перерисовывается с ошибкой, **Then** значения выводятся
   как текст без форматирования.
10. **Given** донос принят, **When** отправка, **Then** HTTP 302 на `/thanks?id={id}`.

### User Story 2 - Страница благодарности с номером (Priority: P1)

**Acceptance Scenarios**:

1. **Given** `GET /thanks?id=7` для существующего доноса, **Then** HTTP 200, выводится номер «7».
2. **Given** `GET /thanks` без параметра, **Then** HTTP 200, выводится текст-заглушка (см. «Тексты вне контракта»).
3. **Given** `GET /thanks?id=99` (нет доноса) или `id=abc`, `0`, `-1`, **Then** HTTP 404, экран «Донос не найден».

### User Story 3 - Модерация списка (Priority: P2)

**Acceptance Scenarios**:

1. **Given** в системе есть доносы, **When** `GET /reports`, **Then** HTTP 200, каждая запись показывает номер,
   имя, группу (если не пусто), уровень, описание, бейдж статуса и кнопки «Подтвердить» и «Отклонить»;
   выводится «Показано {shown} из {total}».
2. **Given** донос в статусе `new`, **When** нажата «Подтвердить», **Then** HTTP 303 на
   `/reports?changed_id={id}&changed_to=confirmed&...`, сверху выводится «Статус доноса №{id}: «Подтверждён».»,
   бейдж строки «Подтверждён».
3. **Given** донос в статусе `confirmed`, **Then** кнопка «Подтвердить» выведена с `disabled`, «Отклонить» активна.
4. **Given** донос в статусе `rejected`, **Then** кнопка «Отклонить» выведена с `disabled`, «Подтвердить» активна.
5. **Given** донос в статусе `new`, **Then** обе кнопки активны.
6. **Given** фильтры `status`, `vibe_level`, `group`, `q` заданы, **When** `GET /reports`, **Then** список
   отфильтрован (AND), поля фильтров сохраняют введённые значения.
7. **Given** `total = 0`, **Then** выводится «Пока пусто. Оставьте первую заявку на главной странице.», фильтры
   и счётчик не выводятся.
8. **Given** `total > 0` и `shown = 0`, **Then** выводится «Нет заявок, подходящих под фильтры.», фильтры и
   счётчик «Показано 0 из {total}» выводятся.
9. **Given** неверный `status` или `vibe_level` в адресе, **Then** HTTP 400, страница «Некорректный запрос.».
10. **Given** нажата «Подтвердить» или «Отклонить» на фильтрованном списке, **When** действие выполнено,
    **Then** список возвращается с теми же фильтрами (через `return_query` и белый список логики).
11. **Given** донос не найден при действии, **Then** HTTP 404, экран «Донос не найден».
12. **Given** ошибка сервера при действии, **Then** HTTP 500, текст «Не удалось изменить статус. Попробуйте ещё раз.».

### User Story 4 - Экран «Донос не найден» и общие страницы (Priority: P3)

**Acceptance Scenarios**:

1. **Given** номер `id` — положительное целое, доноса нет, **Then** HTTP 404, заголовок «Донос не найден»,
   текст «Донос с номером {id} не найден.».
2. **Given** номер некорректный (`abc`, `0`, `-1`), **Then** HTTP 404, заголовок «Донос не найден», текст без номера
   («Запрошенный донос не найден.»).
3. **Given** неизвестный путь (`/foo`), **Then** HTTP 404, страница «Страница не найдена.».

## Экраны и тексты

Колонка «Источник»: **К** — контракт; **Ш** — текущий шаблон; **В** — вне контракта (см. раздел «Тексты вне контракта»).

### Экран 1. Форма отправки (`/`)

| Элемент | Состояние | Текст / значение | Источник |
|---------|-----------|------------------|----------|
| Заголовок | всегда | Сообщить о «вайбкоде» | Ш |
| Подсказка | всегда | Заполните форму ниже. Поля «Имя студента» и «Описание» обязательны. | Ш |
| Поле `name` | всегда | метка «Имя студента», `maxlength="60"` | Ш, К |
| Поле `group` | всегда | метка «Группа (необязательно)», `maxlength="20"` | Ш, К |
| Поле `vibe_level` | всегда | метка «Уровень вайба»; варианты: Низкий (`low`), Средний (`medium`, по умолчанию), Высокий (`high`) | Ш, К |
| Поле `details` | всегда | метка «Описание», многострочное, без `maxlength` | Ш, К |
| Кнопка | всегда | Отправить | Ш |
| Ссылка | всегда | Посмотреть заявки (на `/reports`) | Ш |
| Ошибка под `name` | код `NAME_REQUIRED` | Укажите имя студента. | К |
| Ошибка под `name` | код `NAME_LENGTH` | Имя студента: от 2 до 60 символов. | К |
| Ошибка под `group` | код `GROUP_LENGTH` | Группа: не больше 20 символов. | К |
| Ошибка под `details` | код `DETAILS_REQUIRED` | Опишите ситуацию. | К |
| Ошибка под `details` | код `DETAILS_LENGTH` | Описание: от 10 до 1000 символов. | К |
| Ошибка под `vibe_level` | код `VIBE_INVALID` | Выберите уровень из списка. | К |
| Блок над формой | код `DUPLICATE` (409) | Такой донос уже отправлен. Измените данные и отправьте снова. | К |
| Блок над формой | код `INTERNAL_ERROR` (500) | Не удалось отправить донос. Попробуйте ещё раз. | К |

Состояния:
- **Исходное**: поля пусты, `vibe_level` = medium, ошибок нет.
- **Ошибки полей** (422): тексты под полями по `fields[].code`; значения всех полей сохранены.
- **Дубликат** (409): блок над формой; значения сохранены.
- **Внутренняя ошибка** (500): блок над формой; значения сохранены.
- **Успех** (302): редирект на `/thanks?id={id}`.

Поле «Описание» сохраняет переносы строк и пробелы при перерисовке.

Атрибут `required` у полей «Имя студента» и «Описание» остаётся из текущего шаблона. Из-за него браузер
не отправляет пустую форму, и текст `NAME_REQUIRED` / `DETAILS_REQUIRED` выводится только для значений из
пробелов. Это отмечено в «Открытых пунктах».

| Счётчик | `total > 0` | Показано {shown} из {total} | К |

Запись списка:

| Элемент | Состояние | Текст / значение | Источник |
|---------|-----------|------------------|----------|
| Номер | всегда | №{id} | К (поле записи) |
| Имя | всегда | `name` | К |
| Группа | `group` не пусто | `group` | Ш |
| Уровень | всегда | Бейдж: низкий / средний / высокий | Ш |
| Описание | всегда | `details`, с переносами строк | Ш |
| Бейдж статуса | всегда | На рассмотрении / Подтверждён / Отклонён | К |
| Кнопка | всегда | Подтвердить (`status=confirmed`); `disabled`, если статус уже `confirmed` | К |
| Кнопка | всегда | Отклонить (`status=rejected`); `disabled`, если статус уже `rejected` | К |

Кнопки «Подтвердить» и «Отклонить» — отдельные HTML-формы `POST /reports/{id}/status` со скрытыми полями
`status` и `return_query`. Номер берётся из пути.

Состояния:
- **Список с записями**: фильтры, счётчик, записи, кнопки.
- **Пустой список** (`total = 0`): «Пока пусто. Оставьте первую заявку на главной странице.»; фильтры и
  счётчик скрыты.
- **Пустой результат фильтра** (`total > 0`, `shown = 0`): «Нет заявок, подходящих под фильтры.»;
  фильтры и счётчик «Показано 0 из {total}» выводятся.
- **После смены статуса**: блок сверху, список с сохранёнными фильтрами.
- **Неверный параметр** (400): страница «Некорректный запрос.».

Признаки «пустой список» и «пустой результат фильтра» UI вычисляет сам: `total = 0`, либо `total > 0` и
`shown = 0`.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Форма MUST выводить текст под каждым полем, для которого сервер вернул код в `fields[].code`,
  тексты из таблицы экрана 1.
- **FR-002**: При 422, 409 и 500 MUST сохраняться значения всех полей формы (`name`, `group`, `details`,
  `vibe_level`).
- **FR-003**: Код `DUPLICATE` MUST выводиться блоком над формой, а не под полем.
- **FR-004**: Все значения из запроса и из логики MUST выводиться экранированными.
- **FR-005**: Поля `name` и `group` MUST иметь `maxlength` 60 и 20. Поле `details` MUST NOT иметь `maxlength`.
- **FR-006**: `/thanks` MUST выводить `id`, если он передан и положителен; при `id = null` — заглушку; при
  404 — экран 4.
- **FR-007**: Список MUST выводить для каждой записи бейдж статуса и кнопки «Подтвердить» и «Отклонить».
  Кнопка текущего статуса MUST иметь `disabled`.
- **FR-008**: Список MUST выводить фильтры `status`, `vibe_level`, `group`, `q` и сохранять их значения
  после применения.
- **FR-009**: Список MUST выводить счётчик «Показано {shown} из {total}» при `total > 0`.
- **FR-010**: Список MUST выводить сообщения для пустого списка и пустого результата фильтра по признакам
  из экрана 3.
- **FR-011**: После смены статуса MUST выводиться блок с `changed_id` и `changed_to` по контракту, а список
  MUST отображаться с сохранёнными фильтрами (через `return_query`).
- **FR-012**: Ссылки экспорта MUST содержать текущие фильтры списка.
- **FR-013**: Все ответы 404 на маршрутах с номером MUST выводить экран 4; неизвестный путь MUST выводить
  «Страница не найдена.».
- **FR-014**: Ответ 400 MUST выводить «Некорректный запрос.»; ответ 500 при смене статуса MUST выводить
  текст из экрана 5.
- **FR-015**: Интерфейс MUST работать без JavaScript.

### Key Entities *(include if feature involves data)*

- **Донос** (поля из контракта): `id`, `name`, `group`, `details`, `vibe_level`, `status`, `created_at`.
  UI выводит `id`, `name`, `group`, `details`, `vibe_level`, `status`. `created_at` UI не выводит.
- **Статус**: коды `new`, `confirmed`, `rejected`; подписи На рассмотрении, Подтверждён, Отклонён.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все коды полей формы (`NAME_REQUIRED`, `NAME_LENGTH`, `GROUP_LENGTH`, `DETAILS_REQUIRED`,
  `DETAILS_LENGTH`, `VIBE_INVALID`) и блоки `DUPLICATE` и `INTERNAL_ERROR` выводятся с точным текстом из
  контракта в 100% проверок.
- **SC-002**: После ошибки отправки значения всех полей сохраняются в 100% проверок.
- **SC-003**: Счётчик «Показано X из Y» совпадает с числом выведенных записей во всех комбинациях фильтров.
- **SC-004**: Статус каждой записи читается по тексту бейджа без опоры на цвет.
- **SC-005**: Все экраны работают при отключённом JavaScript.
- **SC-006**: HTML во вводе выводится как текст на всех экранах.

## Тексты вне контракта

Эти тексты не зафиксированы в `contract.md`. Они взяты из текущих шаблонов или из предыдущей версии спеки UI
и подлежат подтверждению:

- «Пока пусто. Оставьте первую заявку на главной странице.» и «Нет заявок, подходящих под фильтры.»
  (текущий `reports.html`).
- Заголовок «Заявки», подсказка формы, текст на `/thanks`, ссылки «Новая заявка» и «Смотреть список»
  (текущие шаблоны).
- «Номер доноса: {id}.» и «Номер доноса не указан. Отправьте донос через форму.» (`/thanks`).

## Что нужно от логики (по контракту)

Раздел содержит только то, что контракт определяет и что использует UI.

**Формы и маршруты:**
- `POST /report`: поля `name`, `group`, `details`, `vibe_level`. Ответы: 302 `Location: /thanks?id={id}`;
  422 `VALIDATION_FAILED` с `fields[]` (HTML-перерисовка для браузера); 409 `DUPLICATE`; 500 `INTERNAL_ERROR`.
- `GET /thanks?id=`: 200 с `id` или `id = null`; 404 `NOT_FOUND` при несуществующем или некорректном `id`.
- `GET /reports?status=&vibe_level=&group=&q=`: 200 с `reports`, `total`, `shown`, `by_status`
  (UI использует `total` и `shown`); 400 `INVALID_STATUS` или `VIBE_INVALID`.
- `POST /reports/{id}/status` с полем `status` и `return_query`: 303
  `Location: /reports?changed_id={id}&changed_to={status}` плюс параметры фильтра из белого списка; 400
  `INVALID_STATUS`; 404 `NOT_FOUND`; 500 `INTERNAL_ERROR`.
- `GET /reports/export?format=csv|json` с фильтрами: файл для скачивания; 400 `INVALID_FORMAT` (UI не
  предоставляет выбор формата вне списка).
- Неизвестный путь: 404.

**Поля записи, которые использует UI:** `id`, `name`, `group`, `details`, `vibe_level`, `status`.

**Коды, которые UI переводит в текст:** см. таблицы экранов 1 и 5.

**Что логика не возвращает и UI не вычисляет:** счётчики, дубликаты, длины, переходы статусов.
UI не показывает `by_status`.
