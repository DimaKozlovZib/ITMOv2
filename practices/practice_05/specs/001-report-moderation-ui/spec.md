## Общие ограничения UI

- Серверный рендеринг (Flask + Jinja), JavaScript не используется. Все состояния передаются через
  перерисовку страницы или редирект.
- Весь видимый пользователю текст на русском языке.
- Весь пользовательский ввод выводится с экранированием, включая значения, возвращаемые в поля формы
  после ошибки.
- Ошибки не полагаются только на цвет: текст ошибки и бейдж статуса содержат явную подпись.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Отправка доноса с ошибками и повтором (Priority: P1)

Студент или преподаватель заполняет форму доноса. Если данные некорректны или донос уже существует,
страница показывает понятное сообщение рядом с проблемным полем, а введённые значения остаются в форме,
чтобы пользователь не вводил их заново.

**Why this priority**: без понятной формы отправки невозможно собрать ни один донос.

**Independent Test**: открыть `/`, отправить пустую форму, проверить тексты под полями и сохранение
введённых значений после исправления и повторной отправки.

**Acceptance Scenarios**:

1. **Given** пользователь на `/`, **When** он отправляет форму с пустым полем «Имя студента», **Then**
   страница снова открывается, под полем выводится текст «Укажите имя студента.», а поле «Описание»
   сохраняет введённое значение.
2. **Given** пользователь на `/`, **When** он отправляет форму с пустым полем «Описание», **Then** под
   полем выводится текст «Опишите ситуацию.», а поле «Имя студента» сохраняет введённое значение.
3. **Given** обе поля пусты, **When** пользователь отправляет форму, **Then** оба сообщения выводятся
   под своими полями одновременно.
4. **Given** введённые значения содержат символы HTML (например, `<b>текст</b>`), **When** страница
   перерисовывается с ошибкой, **Then** значения отображаются как обычный текст, без форматирования.
5. **Given** отправка отклонена как дубликат, **When** страница перерисовывается, **Then** над формой
   выводится блок «Такой донос уже отправлен. Измените данные и отправьте снова.», а введённые значения
   сохранены.
6. **Given** форма отправлена успешно, **When** сервер принял донос, **Then** пользователь переходит
   на `/thanks`.

---

### User Story 2 - Подтверждение с номером доноса (Priority: P1)

После успешной отправки пользователь видит страницу благодарности с номером своего доноса, по которому
его можно найти в списке.

**Why this priority**: номер подтверждает, что донос принят, и связывает отправку со списком.

**Independent Test**: успешно отправить донос и проверить, что на `/thanks` выведен номер.

**Acceptance Scenarios**:

1. **Given** донос принят, **When** открывается `/thanks`, **Then** выводится «Спасибо!» и текст
   «Донос принят. Номер доноса: {номер}.», где номер совпадает с номером в списке `/reports`.
2. **Given** пользователь открывает `/thanks` без данных о доносе, **When** страница загружается,
   **Then** выводится текст «Номер доноса не указан. Отправьте донос через форму.», а также ссылка на `/`.
3. **Given** страница `/thanks`, **When** пользователь нажимает «Посмотреть все доносы», **Then** он
   переходит на `/reports`.

---

### User Story 3 - Модерация списка доносов (Priority: P2)

Модератор открывает список доносов, видит статус каждого доноса, фильтрует список по статусу и
подтверждает или отклоняет донос.

**Why this priority**: модерация — основная цель фичи, но для работы нужна уже готовая отправка.

**Independent Test**: отправить несколько доносов, на `/reports` сменить статус одного из них кнопками,
применить фильтр и проверить счётчик.

**Acceptance Scenarios**:

1. **Given** в списке есть доносы, **When** открывается `/reports`, **Then** каждая строка содержит
   номер, имя студента, описание, бейдж статуса и кнопки «Подтвердить» и «Отклонить», а над списком
   выводится «Показано {X} из {Y}», где X и Y равны общему количеству доносов.
2. **Given** пользователь нажимает «Подтвердить» у доноса, **When** действие выполнено, **Then** страница
   снова открывается, бейдж строки показывает «Подтверждён», а сверху выводится «Статус доноса №{номер}
   изменён: «Подтверждён».».
3. **Given** пользователь нажимает «Отклонить», **When** действие выполнено, **Then** бейдж строки
   показывает «Отклонён», а сверху выводится «Статус доноса №{номер} изменён: «Отклонён».».
4. **Given** пользователь выбирает в фильтре статус «Подтверждён», **When** применяет фильтр, **Then**
   в списке остаются только доносы с этим статусом, а счётчик показывает «Показано {X} из {Y}», где Y
   всё ещё общее количество доносов.
5. **Given** в системе нет ни одного доноса, **When** открывается `/reports`, **Then** вместо таблицы
   выводится «Доносов пока нет.», фильтр и счётчик не выводятся.
6. **Given** доносы есть, но ни один не соответствует выбранному статусу, **When** пользователь применяет
   фильтр, **Then** выводится «По выбранному статусу доносов нет.» и ссылка «Показать все доносы»,
   счётчик показывает «Показано 0 из {Y}».

### User Story 4 - Донос не найден (Priority: P3)

Если пользователь открывает или пытается изменить донос, которого нет (например, после перезапуска
сервера, когда данные очищаются), он видит понятную страницу с возможностью вернуться.

**Why this priority**: это крайний случай, но без него пользователь видит общую ошибку.

**Independent Test**: открыть ссылку на несуществующий донос и проверить заголовок, текст и ссылки.

**Acceptance Scenarios**:

1. **Given** донос с запрошенным номером отсутствует, **When** открывается его страница, **Then**
   выводится заголовок «Донос не найден», текст «Донос с номером {номер} не найден. Возможно, сервер
   был перезапущен и данные очищены.» и ссылки «Вернуться к списку доносов» (на `/reports`) и
   «Отправить донос» (на `/`).
2. **Given** донос был удалён (очищен) между открытием списка и нажатием кнопки, **When** пользователь
   нажимает «Подтвердить» или «Отклонить», **Then** открывается страница «Донос не найден».

## Экраны и тексты

### Экран 1. Форма отправки (`/`)

| Элемент | Состояние | Текст |
|---------|-----------|-------|
| Заголовок | всегда | Отправить донос |
| Поле | всегда | Имя студента |
| Поле | всегда | Описание |
| Кнопка | всегда | Отправить |
| Ошибка под полем «Имя студента» | пустое поле | Укажите имя студента. |
| Ошибка под полем «Описание» | пустое поле | Опишите ситуацию. |
| Блок над формой | дубликат | Такой донос уже отправлен. Измените данные и отправьте снова. |
| Блок над формой | внутренняя ошибка сервера | Не удалось отправить донос. Попробуйте ещё раз. |

Состояния экрана:
- **Исходное**: поля пусты, ошибок нет.
- **Ошибка полей**: сообщения выводятся под полями, значения всех полей сохранены.
- **Дубликат**: блок над формой, значения сохранены.
- **Внутренняя ошибка**: блок над формой, значения сохранены.
- **Успех**: редирект на `/thanks`, форма не выводится.

Поле «Описание» выводится многострочным. Пробелы и переносы строк при возврате с ошибкой сохраняются.

### Экран 2. Благодарность (`/thanks`)

| Элемент | Состояние | Текст |
|---------|-----------|-------|
| Заголовок | всегда | Спасибо! |
| Текст | номер доступен | Донос принят. Номер доноса: {номер}. |
| Текст | номер не указан | Номер доноса не указан. Отправьте донос через форму. |
| Ссылка | всегда | Отправить ещё один донос (на `/`) |
| Ссылка | всегда | Посмотреть все доносы (на `/reports`) |

### Экран 3. Список доносов (`/reports`)

| Элемент | Состояние | Текст |
|---------|-----------|-------|
| Заголовок | всегда | Список доносов |
| Фильтр | всегда | Статус: «Все статусы», «На рассмотрении», «Подтверждён», «Отклонён» |
| Счётчик | доносы есть | Показано {X} из {Y} |
| Заголовки колонок | список не пуст | Номер, Имя студента, Описание, Статус, Действия |
| Бейдж статуса | на каждой строке | На рассмотрении / Подтверждён / Отклонён |
| Кнопка | на каждой строке | Подтвердить |
| Кнопка | на каждой строке | Отклонить |
| Сообщение | список пуст | Доносов пока нет. |
| Сообщение | фильтр не нашёл доносов | По выбранному статусу доносов нет. |
| Ссылка | фильтр не нашёл доносов | Показать все доносы |
| Блок сверху | после действия | Статус доноса №{номер} изменён: «{статус}». |

Состояния экрана:
- **Список с доносами**: таблица, счётчик, фильтр, кнопки.
- **Пустой список**: сообщение «Доносов пока нет.». Фильтр и счётчик скрыты.
- **Пустой результат фильтра**: фильтр и счётчик «Показано 0 из {Y}» выводятся, таблица заменяется
  сообщением.
- **После действия**: блок-подтверждение сверху, список перерисован с новым бейджем.

Бейдж содержит текст статуса и отдельный визуальный стиль. Цвет без текста не используется.

### Экран 4. Донос не найден

| Элемент | Состояние | Текст |
|---------|-----------|-------|
| Заголовок | всегда | Донос не найден |
| Текст | всегда | Донос с номером {номер} не найден. Возможно, сервер был перезапущен и данные очищены. |
| Ссылка | всегда | Вернуться к списку доносов (на `/reports`) |
| Ссылка | всегда | Отправить донос (на `/`) |

Экран не содержит кнопок действий и не предлагает повторить запрос.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Форма отправки MUST выводить текст ошибки под каждым полем, для которого сервер вернул
  ошибку, используя тексты из раздела «Экраны и тексты».
- **FR-002**: При любой ошибке отправки MUST сохраняться введённые значения всех полей формы.
- **FR-003**: Состояние «дубликат» MUST выводиться блоком над формой, а не ошибкой конкретного поля.
- **FR-004**: Все пользовательские значения MUST выводиться экранированными, включая значения,
  возвращаемые в форму после ошибки.
- **FR-005**: Страница `/thanks` MUST выводить номер доноса, если он передан, и текст-заглушку, если
  номер не передан.
- **FR-006**: Список `/reports` MUST выводить для каждого доноса бейдж статуса и кнопки «Подтвердить»
  и «Отклонить».
- **FR-007**: Список `/reports` MUST выводить фильтр по статусу с вариантами «Все статусы»,
  «На рассмотрении», «Подтверждён», «Отклонён».
- **FR-008**: Список `/reports` MUST выводить счётчик «Показано {X} из {Y}», где Y — общее количество
  доносов, а X — количество строк, которые видит пользователь (с учётом фильтра).
- **FR-009**: Список `/reports` MUST показывать сообщения для пустого списка и для пустого результата
  фильтра, как описано в экране 3.
- **FR-010**: Страница «Донос не найден» MUST открываться, когда запрошенный донос отсутствует, и
  содержать ссылки на `/reports` и `/`.
- **FR-011**: Интерфейс MUST работать без JavaScript: все действия выполняются отправкой формы или
  переходом по ссылке.

### Key Entities *(include if feature involves data)*

- **Донос**: имя студента, описание, номер доноса, статус. Номер и статус назначаются и хранятся
  логикой; UI только отображает их.
- **Статус доноса**: одно из значений «На рассмотрении», «Подтверждён», «Отклонён». Набор значений и
  их коды определяет логика (см. раздел «Что мне нужно от логики»).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все пять вариантов ошибок формы (пустое имя, пустое описание, оба пустых, дубликат,
  внутренняя ошибка) отображаются с точным текстом из таблицы в 100% проверок.
- **SC-002**: После любой ошибки отправки введённые значения сохраняются в 100% проверок.
- **SC-003**: Счётчик «Показано X из Y» совпадает с фактическим количеством строк в 100% проверок,
  включая фильтры.
- **SC-004**: Пользователь может определить статус каждого доноса по тексту бейджа без опоры на цвет.
- **SC-005**: Все экраны работают при полностью отключённом JavaScript.
- **SC-006**: Введённый HTML-код выводится как обычный текст во всех экранах в 100% проверок.

## Assumptions

- Тексты ошибок и сообщений из раздела «Экраны и тексты» являются предложением UI и подлежат
  согласованию. Условия возникновения ошибок (например, правила валидации и проверки дубликатов)
  определяет логика.
- Тексты статусов («На рассмотрении», «Подтверждён», «Отклонён») — отображаемые подписи. Внутренние
  коды статусов определяет логика.
- Данные хранятся в памяти процесса, поэтому номера доносов и статусы не переживают перезапуск сервера
  (ожидаемое поведение по README).
- Фильтр и кнопки действий работают через перезагрузку страницы, без асинхронных запросов.
- Существующие шаблоны `index.html`, `reports.html`, `thanks.html` и `base.html` используются как
  основа; новые шаблоны (например, для «Донос не найден») допускаются при согласовании.
- Любое изменение общего контракта между UI и логикой сначала фиксируется в `practice-05/contract.md`
  (по конституции). Каталог `practices/practice-05` в репозитории отсутствует, поэтому этот шаг
  остаётся открытым.

## Что мне нужно от логики

Раздел перечисляет ожидания UI. Решения принимает команда логики; UI не задаёт их самостоятельно.

**Маршруты и методы (ожидаю подтверждения):**
- `GET /`, `POST /report` (существующие).
- `GET /thanks` с передачей номера доноса. Способ передачи (параметр запроса, сессия или иной) не
  определён. Нужно подтверждение.
- `GET /reports` с параметром фильтра по статусу (например, `status`). Значения «Все статусы» должны
  соответствовать отсутствию параметра или явному значению `all`. Нужно подтверждение.
- Действия модерации: отдельные маршруты `POST` для «Подтвердить» и «Отклонить», принимающие номер
  доноса. Нужно подтверждение имён и методов.
- Страница одного доноса (для экрана 4), если она предусмотрена. Маршрут не описан в README.

**Данные, которые ожидаю в шаблонах:**
- Список доносов: для каждого номер, имя студента, описание, статус.
- Общее количество доносов (Y) и количество отображаемых после фильтра (X).
- Номер только что созданного доноса для `/thanks`.
- Текущее значение фильтра, чтобы отметить его в селекте.
- Признак «список пуст» и признак «фильтр не нашёл доносов», отдельно друг от друга.

**Коды ошибок формы, которые ожидаю получить и сопоставить с текстами:**
- `NAME_REQUIRED` → «Укажите имя студента.»
- `DETAILS_REQUIRED` → «Опишите ситуацию.»
- `DUPLICATE` → «Такой донос уже отправлен. Измените данные и отправьте снова.»
- `INTERNAL_ERROR` → «Не удалось отправить донос. Попробуйте ещё раз.»
- Любые дополнительные коды валидации (например, ограничения длины): нужен список кодов и условий
  срабатывания, а также текст для каждого. Текст UI не будет придуман без этого списка.

**Коды результата действий модерации:**
- Успех: номер доноса и новый статус для текста подтверждения.
- Донос не найден: код, по которому UI открывает страницу «Донос не найден».
- Ошибка отправки действия: код и текст, если отличается от общей внутренней ошибки.

**Статусы:**
- Полный набор кодов статусов и переходы между ними: можно ли вернуть «Отклонён» в «Подтверждён»,
  и наоборот. От ответа зависит, показывать ли кнопки для уже обработанного донос. UI пока показывает
  обе кнопки для любого статуса.
