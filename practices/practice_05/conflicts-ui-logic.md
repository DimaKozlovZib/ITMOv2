# Конфликты между спецификациями UI и логики

**Дата**: 2026-10-22
**Источники**:
- UI: `specs/001-report-moderation-ui/spec.md`
- Логика: `specs/002-report-moderation-logic/spec.md`
  (файл `hw5/specs-before/logic.md` в репозитории отсутствует)
- Копии в `practices/practice_05/specs/` идентичны корневым файлам (проверено по хешу).

## Таблица конфликтов

| № | Проверка | Я ожидаю (UI) | Предлагает логика | Несовместимость | Моё решение |
|---|----------|---------------|-------------------|-----------------|-------------|
| 1 | Имена полей формы | `name`, `details`. `group` и `vibe_level` не описаны | `name`, `group`, `details`, `vibe_level` (по умолчанию `medium`) | В UI нет полей `group` и `vibe_level` | Добавить «Группа» (необязательное, до 20 символов) и «Уровень» (select: low, medium, high; предвыбран medium) |
| 2 | Имена параметров фильтра | Только фильтр по статусу, имя не задано | `status`, `vibe_level`, `group`, `q` | В UI нет фильтров по уровню, группе и поиску | Добавить select `vibe_level` (any, low, medium, high), текстовые `group` и `q`. «Все статусы» передаётся как `status=all` |
| 3 | Параметр для `/thanks` | Номер доноса, имя не задано | `id` | Нет | Принять `id` |
| 4 | Параметр после смены статуса | Список снова открывается с сообщением о смене | `Location: /reports?updated={id}&status={status}` | Параметр `status` совпадает с фильтром списка. После подтверждения список фильтруется по новому статусу, и донос может исчезнуть (например, в фильтре «Отклонён») | Просить логику переименовать параметр в `changed_to={status}`. До ответа UI не использует `status` в этом редиректе |
| 5 | Формат ошибок (`POST /report`, `POST /reports/{id}/status`) | HTML-страница: при ошибке перерисовка формы с сохранёнными значениями и текстом у полей | JSON: `{"error":{"code":"...","fields":[{"field","code"}]}}`. Значения полей логика не возвращает | Браузеру нужен HTML, а не JSON | JSON остаётся внутренним контрактом между логикой и маршрутами `server.py`. Браузер получает HTML с тем же HTTP-кодом (422, 409, 404). Введённые значения берутся из `request.form` |
| 6 | Коды полей формы | `NAME_REQUIRED`, `DETAILS_REQUIRED` как верхний уровень ответа | Внутри `fields[].code`, верхний код `VALIDATION_FAILED` | Расхождение структуры | UI читает код из `fields[].code`. `DUPLICATE` и `INTERNAL_ERROR` приходят на верхнем уровне |
| 7 | Тексты ошибок формы | Только для `NAME_REQUIRED`, `DETAILS_REQUIRED`, `DUPLICATE`, `INTERNAL_ERROR` | Добавлены `NAME_LENGTH`, `GROUP_LENGTH`, `DETAILS_LENGTH`, `VIBE_INVALID` | Для четырёх кодов нет текстов | Предлагаю: `NAME_LENGTH` «Имя студента: от 2 до 60 символов.»; `GROUP_LENGTH` «Группа: не больше 20 символов.»; `DETAILS_LENGTH` «Описание: от 10 до 1000 символов.»; `VIBE_INVALID` «Выберите уровень из списка.» |
| 8 | Коды ответов `POST /report` | 302, 422 (перерисовка), 409, 500 | 302, 422, 409, 500 | Нет | Принять |
| 9 | Ответ на смену статуса | Сообщение «Статус доноса №N изменён» | 303 также при no-op (статус не менялся) | Сообщение «изменён» может быть неверным | Нейтральный текст: «Статус доноса №{номер}: «{статус}».» |
| 10 | Ошибки смены статуса | Текст не задан | 400 `INVALID_STATUS` (из UI недостижим), 404 `NOT_FOUND`, 500 `INTERNAL_ERROR` | Нет текста для 500 | 500: «Не удалось изменить статус. Попробуйте ещё раз.» 400: общая страница «Некорректный запрос.» (предложение, нужно согласовать) |
| 11 | Значения статусов | «На рассмотрении», «Подтверждён», «Отклонён» | `new`, `confirmed`, `rejected` | Нет, соответствие 1:1 | Принять коды; подписи задаёт UI |
| 12 | Переходы статусов | Кнопки «Подтвердить» и «Отклонить» на каждой строке. Вопрос о возврате не был закрыт | `rejected` ↔ `confirmed` разрешены, в `new` вернуться нельзя, повтор текущего статуса = успех | Нет | Оставить обе кнопки. Кнопка текущего статуса выводится с атрибутом `disabled` (HTML, без JS) |
| 13 | Успешная отправка | Редирект на `/thanks` | 302 на `/thanks?id={id}` | Нет | Принять |
| 14 | `/thanks` без `id` | Текст «Номер доноса не указан» | 200 с `id=null` | Нет | Принять |
| 15 | `/thanks` с несуществующим `id` | Не описан | 404 `NOT_FOUND` (включая `id=abc`, `id=0`) | Нет экрана | 404 → экран «Донос не найден» |
| 16 | Несуществующий донос при смене статуса | Экран «Донос не найден» | 404 `NOT_FOUND` | Нет | Принять. Номер берётся из пути. Если номер не положительное целое, текст выводится без номера |
| 17 | Неизвестный путь (`/foo`) | Экран «Донос не найден» на любой 404 | 404 без кода (логика не различает) | Для `/foo` текст неверен | Отдельная страница «Страница не найдена.» (предложение, нужно согласовать) |
| 18 | Просмотр одного доноса `GET /reports/{id}` | Экран 4 подразумевает страницу доноса, отдельного экрана нет | 200 с записью, формат (JSON или HTML) не определён | Неясно, HTML или JSON | UI не делает отдельную страницу. Маршрут используется только как API. Экран 4 остаётся для `/thanks` и смены статуса |
| 19 | Границы `name`, `group`, `details` | Только проверка на пустоту | `name` 2–60, `group` 0–20, `details` 10–1000 после обрезки; `\r\n` считается одним символом | Нет подсказок для пользователя | Атрибут `maxlength` для `name` (60) и `group` (20). Для `details` не ставлю, браузеры по-разному считают переносы строк в `textarea`. Окончательная проверка на сервере |
| 20 | Пустой список и пустой фильтр | `total=0` → «Доносов пока нет.»; `shown=0` при `total>0` → «По выбранному статусу доносов нет.» | `total`, `shown`, те же условия | Нет | Принять |
| 21 | Счётчик «Показано X из Y» | X = `shown`, Y = `total` | `shown`, `total` | Нет | Принять. `by_status` необязателен, можно вывести в подписях фильтра |
| 22 | Экспорт | Не описан | `GET /reports/export?format=csv|json` с фильтрами, 400 `INVALID_FORMAT` | Нет UI | Добавить ссылки «Скачать CSV» и «Скачать JSON» с текущими фильтрами в query. 400 не выводится: значения выбираются из списка |
| 23 | Неверные значения фильтров (`vibe_level`, `status`) | Не описаны | 400 `VIBE_INVALID` / `INVALID_STATUS` | Нет | Общая страница «Некорректный запрос.» (предложение) |
| 24 | Экран «Донос не найден» после перезапуска | Текст «Возможно, сервер был перезапущен» | Номера переиспользуются после перезапуска | Номер может указывать на другой донос | Оставить текст. Логика подтверждает ожидаемость поведения |

## Что нужно подтвердить логике

1. Формат ошибок для браузерных маршрутов: JSON остаётся внутренним контрактом, браузер получает HTML (строка 5).
2. Переименование параметра редиректа `status` в `changed_to` (строка 4). Без этого список может скрыть донос сразу после действия.
3. Статус ответа на `GET /reports/{id}` и нужен ли он UI вообще (строка 18).
4. Защита от формульной инъекции в CSV (открытый вопрос логики № 3). UI на CSV не влияет.

## Замечания

- Конституция (раздел V) требует фиксации контракта в `practices/practice-05/contract.md` до реализации. Каталог `practices/practice-05` отсутствует. Есть `practices/practice_05` (с подчёркиванием) с копиями спек. Файл `contract.md` не создан. После согласования пунктов 1-3 его стоит создать.
