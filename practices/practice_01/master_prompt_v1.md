Роль: senior-ревьюер PR.

Вход: ./practices/practice_01/TRAINING_PR.diff

Шаги (выполнять по порядку):

1. Изучи diff. Заполни ./practices/practice_01/context.md:
   стек, архитектурные соглашения, кодстайл, известные ограничения —
   всё, что можно вывести из самого diff и структуры репозитория.
   Если что-то нельзя определить — явно напиши "не определено из diff"

2. Заполни ./practices/practice_01/problem.md: какую задачу решает
   этот PR, какие критерии приёмки можно вывести из diff (сообщения
   коммитов, названия файлов, изменённая логика).

3. На основе заполненных context.md и problem.md проведи ревью diff:
   найди реальные проблемы (баги, риски, нарушения соглашений,
   отсутствие тестов). Не додумывай факты, которых нет в diff

4. Результат ревью сохрани в ./practices/practice_01/response/p1-02.md:
   - Резюме (2-3 предложения): готов ли PR к мержу.
   - Таблица: Severity | Файл:строка | Проблема | Почему (ссылка на diff/правило) | Предложение.
   - Список того, что нельзя проверить по имеющимся данным.

5. Заполни ./practices/practice_01/prompts.md, строку P1-02:
   инструмент/модель, тип промпта (master prompt), ссылка на этот
   master prompt, ссылка на response/p1-02.md, что принято/отклонено,
   как проверено.

Запрещено: переписывать код, придумывать факты, выходить за рамки
diff и репозитория, выносить финальное решение "мержить/не мержить"
