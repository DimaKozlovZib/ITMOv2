# Проблема и метрики

## Проблема

- Пользователь: разработчик/ревьюер PR.
- Ситуация: отправляет diff в сервис для получения подсказок по ревью.
- Что происходит сейчас: сервис формирует prompt из полного diff без редактирования секретов и без ограничений размера, синхронно вызывает внешний LLM без таймаута и возвращает ответ в виде `{"comment": answer}` (не соответствует требуемой структуре OUT-1). Evidence: app/review_service.py:13–16; app/api.py:8–10; OUT-1.
- Почему это мешает пользователю или бизнесу: риск утечки секретов (SEC-1), отказ на больших diff'ах без понятного ответа (API-1), подвисание/нестабильность при недоступности LLM (REL-1), сложно автоматизировать проверки из-за неверного формата ответа (OUT-1). Источник: CASE.md:64–71.
- Что не входит в задачу: одобрение/merge PR, изменения кода репозитория пользователя, генерация кода (SCOPE-1).

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля ответов в требуемом формате OUT-1 | Проверка схемы: наличие `summary`, `risks` (≤3), `checks` | 0% → 100% | При каждом ответе сервиса | OUT-1; e2e тест |
| Доля редактированных секретов в prompt | Тестовый diff с токеном → в prompt [REDACTED] | 0% → 100% | Перед вызовом LLM | SEC-1; unit тест |
| Доля отказов на diff > 20k | Отправка 21k символов → HTTP 413 | 0% → 100% корректных отказов | При запросе >20k | API-1; integration тест |
| Таймаут LLM-вызова | Вызов с задержкой >10s → контролируемый ответ | Не ограничено → ≤10s | При деградации LLM | REL-1; integration тест |
Приведение формата ответа к OUT-1 делает результат пригодным для автоматических проверок и сопоставимо с требуемыми артефактами. Редактирование секретов снижает риск утечки и соответствует SEC-1. Ограничение размера diff и корректный отказ с 413 подтверждают соблюдение API-1. Таймаут и контролируемая ошибка по REL-1 предотвращают зависания и стабилизируют сервис.
