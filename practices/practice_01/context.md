## Context Pack для первого рабочего сценария

### Факты и правила

- Задача помощника: для одного PR на вход получает diff и возвращает summary, ≤3 риска с `file,line,evidence,risk`, и список checks. Решает человек (не approve/merge). Источник: CASE.md:52–61, 67–71 (OUT-1, SCOPE-1, QA-1).
- Правила репозитория: SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1. Источник: CASE.md:64–71.
- В учебном diff реализованы: POST `/api/reviews` (app/api.py:8–10), сервис `ReviewService.review` формирует prompt из полного diff и возвращает `{"comment": answer}` (app/review_service.py:13–16).

### Формат входа и результата

- Вход: строка `diff` из PR. Источник: app/api.py:8–10.
- Результат: объект с полями `summary: str`, `risks: [{file,line,evidence,risk}]` (≤3), `checks: [str]`. Источник: OUT-1 (CASE.md:67–71).

### Ограничения и запрещённые действия

- Нельзя отправлять секреты/токены/приватные ключи в LLM (SEC-1).
- Diff > 20 000 символов отклоняется с HTTP 413 (API-1).
- Вызов внешнего LLM — таймаут 10 секунд, ошибка преобразуется в контролируемый ответ (REL-1).
- Сервис только советует, не пишет код и не выполняет действия в GitHub (SCOPE-1).
- В лог пишутся только request_id, длительность и статус; содержимое diff и ответ модели не логируются (OBS-1).

### Хороший пример

app/review_service.py:14 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED]. Источник: CASE.md:81–85; SEC-1; app/review_service.py:14–15.

### Плохой пример

«Код можно улучшить. Добавьте тесты и обработку ошибок.» Источник: CASE.md:89–91.

### Что пока неизвестно

- Где именно реализовывать редактирование (до/после API) — требует уточнения.
- Формат и структура логов (request_id генерация) — требует уточнения (OBS-1 есть, реализация неизвестна).
- Схема валидации входного JSON и типы ошибок на уровне API — требует уточнения.

## Как использовали AI

- Для чего: структурировать Context Pack и зафиксировать факты/правила из CASE.md, привязать evidence к diff.
- Тип промпта: master prompt (см. P1-02).
- Строка в [`prompts.md`](prompts.md): P1-02.
- Что проверили и исправили сами: вручную сверили `file:line` по TRAINING_PR.diff и соответствие пунктам SEC-1, API-1, REL-1, OUT-1.
