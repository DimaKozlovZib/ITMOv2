# ReAct

- Цель: Определить, какие правила репозитория из CASE.md (SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1) поддаются unit-проверке в изоляции, но отсутствуют в текущей таблице tests_unit.md, и сформулировать для них строки таблицы (требование, вход, ожидаемый результат, evidence), не задваивая их с tests_integration.md/tests_load.md.
- Доступные входы: `CASE.md`, текущая таблица `tests_unit.md`, `tests_integration.md`, `tests_load.md`, `tests_e2e` — только для проверки, что правило уже не покрыто там.
- Разрешённые действия:
  - Прочитать содержимое файлов (`CASE.md`, `tests_unit.md`, `tests_integration.md`, `tests_load.md`б `tests_e2e`);
  - Сравнить список правил `CASE.md` со списком правил, уже покрытых в `tests_unit.md`, и вернуть недостающие;
- Запрещённые действия: придумывать правила, которых нет в `CASE.md`; менять файлы кроме `tests_unit`; 
- Максимальное число шагов: 6
-  Условие остановки и вопроса человеку: остановиться после того, как для каждого из семи правил CASE.md определено, относится ли оно к unit-уровню, и агент вызвал update_file, дописав в tests_unit.md строки только для unit-правил.
